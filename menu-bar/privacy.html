Transparent Data Practices

Privacy Center

Last Updated: October 2026 ● Zero Server Storage ● Zero Tracking Cookies

PDFHub is built around a simple principle: your documents belong to you. Understand how our browser-based tools process files, when external services are contacted, and how your local preferences are managed.

Client-Side Processing

Standard PDF tools execute entirely within your browser's local memory via WebAssembly and JavaScript. Your documents are not uploaded to PDFHub servers.

Zero Server Storage

We maintain no file storage infrastructure, no user database, and no document logging servers. Files disappear from memory when you close your tab.

No Accounts or Tracking

No user accounts, passwords, or emails required to use any tool. We do not set tracking cookies or embed advertising telemetry pixels.

Declared Network Needs

Where a feature relies on an external service (such as translation or OCR language downloads), that network activity is disclosed explicitly below.

Architecture

How PDFHub processes files locally in your browser

Traditional online PDF websites require uploading your documents to remote cloud servers, transforming them in a datacenter, and sending a download link back. PDFHub takes a fundamentally different, privacy-first approach:

1
Local File Reading via HTML5 File API

When you drag or select a PDF, your browser reads its binary data into temporary local memory (ArrayBuffer) directly on your device.

2
In-Memory Transformations via Client-Side Engines

Our tools utilize audited client-side engines such as pdf-lib, PDF.js, HTML5 Canvas, and docx/xlsx libraries executing entirely within your browser sandbox.

3
Local Blob Export Directly to Your Storage

The resulting modified PDF is packaged into a local binary object URL (blob:) and saved to your device's downloads folder. The file never leaves your computer.

External Resources

Third-party CDNs and network dependencies

PDFHub is delivered as a static web application hosted on Cloudflare Workers and Netlify. To deliver fast global performance and dependable typography, the site loads the following static third-party resources:

Cloudflare cdnjs (cdnjs.cloudflare.com)

Delivers static JavaScript libraries (pdf-lib, pdf.js, font-awesome, docx, xlsx, pptxgenjs, tesseract.js). Subject to Cloudflare's privacy policy. No document contents are sent to cdnjs.

Google Fonts (fonts.googleapis.com)

Delivers web fonts (Syne, DM Sans). Subject to Google Fonts' privacy policy. Google receives standard browser HTTP request metadata (IP address, user-agent) to serve font stylesheets.

MyMemory Translated API (api.mymemory.translated.net)

Used exclusively by the Translate PDF tool when a translation request is initiated by the user. Only the text chunks to be translated are sent.

Tesseract CDN (unpkg.com)

Used by the OCR tool to download pre-trained language model data files (e.g. eng.traineddata). Document content is not sent to unpkg.

Local Storage

Application data stored in your browser

PDFHub uses HTML5 localStorage exclusively to save your interface preferences. It does not use tracking cookies, analytics identifiers, or cross-site tokens. Here is the complete inventory of keys stored:

pdfhub-theme String ('dark' | 'light')

Preserves your chosen color theme so your preference is retained when navigating between pages or revisiting the site.

pdfhub-favorites JSON Array

Stores the list of tool URLs that you have starred on the homepage for fast one-click access.

pdfhub-history-tools JSON Array (max 12 items)

Stores the names and URLs of the last tools you opened so you can quickly return to recent utilities from the menu or dashboard.

pdfhub-notifications-seen String ('true' | 'false')

Records whether you have viewed local update announcements in the dashboard to prevent showing repeated notices.

Security & Best Practices

Security limitations & user responsibilities

While client-side processing eliminates interception risks over transit to an application server, browser-based tools carry specific considerations:

Public & Shared Computers

If you process private documents on a shared library, school, or workplace computer, subsequent users could potentially view recent tool URLs in browser history or recover files left in the browser's download folder. Always use the Clear Local PDFHub Data action above and close all browser windows when finished.

Browser Extension Safety

Third-party browser extensions (such as screen recorders, ad blockers, or grammar checkers) have broad permissions to inspect web pages. Avoid running untrusted browser extensions when working with sensitive legal, financial, or personal records.

Keep Original Source Backups

PDF operations like page deletion, splitting, and compression permanently alter document structure. Never rely exclusively on a modified output without retaining an unmodified backup of your original document.

Privacy questions or security disclosures?

If you have questions about how a particular tool works or wish to report a security finding, contact the developer directly.
